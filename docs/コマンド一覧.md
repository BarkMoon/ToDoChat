# チャットコマンド一覧

入力欄に下記のスラッシュコマンドを送信すると、通常の AI への発言ではなく **アプリ側の操作**として処理される（AI へは送られない。ただし `/remember` `/save` `/refresh` は内部で AI に記憶スナップショットを依頼する）。

実装は `app/index.html` の `send()` 内の分岐、および `app/server.py` の対応 API。

---

## 用語

- **フルログ** … `.todochat/transcripts/` に記録された会話全文のミラー（直近200ターン）＋ `.todochat/sessions.json` の `session_id`（CLIセッションの実体）。端末間同期や `--resume` 復元に使う。トークンを多く消費する。
- **記憶ログ** … `.todochat/memory/` に保存される、引き継ぐべき進行中状態の**要約ノート**。起動時挨拶に注入される軽量な引き継ぎメモ。
- **起動時挨拶** … `/api/init`。フォルダ用に新しい CLI セッションを開始し、TASKS.md と記憶ログを注入して「現在の状況／次のタスク／確認」を生成する。

---

## コマンド

### `/startup` — 起動時挨拶を再表示
現在のフォルダで起動時挨拶を手動でもう一度生成・表示する。サーバー側で新しいセッションが始まる（＝改めて起動し直す動作。軽い再要約ではない）。
実装: `showStartup()` → `/api/init`

### `/new` — 履歴を消して新しく始める
`/clear` 相当（フルログ・記憶ログ・セッションをすべて破棄）に続けて起動時挨拶を表示し、まっさらな状態から会話を始め直す。
実装: `newConversation()` → `clearHistory(false)` → `showStartup()`

### `/save` — 記憶へ圧縮してフルログを削除
終了時記憶と同じ経路でいまの状態を**記憶ログへスナップショット保存**したうえで、**記憶ノートは残したまま**フルログ（transcript＋session_id）だけを削除する。次回起動を重い会話ログの replay ではなく要約から再開させ、トークンを節約する目的。
実装: `saveAndClearLog()` → `/api/remember` → `/api/clear-log`（`clear_log()`）

### `/refresh` — 圧縮して新しい会話を開始
`/save`（記憶へ圧縮＋フルログ削除）に続けて `/startup`（新しい挨拶）を実行する。やり取りを記憶ログへ圧縮したうえで、新しいチャットを即座に始め直す。
実装: `refreshConversation()` → `saveAndClearLog()` → `showStartup()`

### `/remember` — 今すぐ記憶ログへ保存
AI の自己判断を待たず、現在の状態を**手動で記憶ログへ強制スナップショット**する。既存セッションを resume して記憶ブロックのみを要求し、通常の保存経路で `.todochat/memory/` に書き込む。フルログは削除しない。
実装: `rememberSnapshot()` → `/api/remember`

### `/clear` — 履歴も記憶も消去
このプロジェクトの会話継続（セッション）と記憶ログを破棄し、画面ログを消す。削除前に記憶ノートは `.todochat/trash/` にバックアップされる（trash はサーバーが一切読まないためトークンを消費しない）。挨拶は自動表示しない。
実装: `clearHistory()` → `/api/clear`

## 使い分けの早見表

| やりたいこと | コマンド | フルログ | 記憶ログ | 挨拶 |
|---|---|---|---|---|
| もう一度挨拶を見たい | `/startup` | 保持 | 保持 | 表示 |
| 全部消してゼロから | `/new` | 削除 | 削除 | 表示 |
| 一区切り・トークン節約して続行 | `/save` | 削除 | **保存** | なし |
| 圧縮して新しい会話へ | `/refresh` | 削除 | **保存** | 表示 |
| 今の状態だけ記憶に残す | `/remember` | 保持 | **保存** | なし |
| 履歴も記憶も破棄 | `/clear` | 削除 | 削除 | なし |

## 補足: 起動・再接続時の自動挙動

アプリ起動やスマホ合流などの**再接続時**は、`.todochat/transcripts/` に会話が残っていればそれを画面へ復元するだけで、**起動時挨拶は自動実行しない**（セッションの意図しないリセットを防ぐため）。履歴がまだ無いフォルダのみ、従来どおり自動で挨拶を表示する。手動で挨拶を出したいときは `/startup` を使う。
実装: `init()`（`app/index.html`）

## 補足: 終了時の自動挙動（フルログ復元トグルとの連携）

上記のとおり再接続時はセッションを保ったままにする設計のため、**フルログ復元トグルが OFF でも、起動側だけでは次回起動時に前回の会話が resume されてしまう**（再接続とアプリ再起動をアプリ側では区別できないため）。これを避けるため、リセットは「起動時」ではなく**「正常終了時」**に行う。

✕終了ボタン、またはウィンドウを閉じてサーバーが終了する（＝`_shutdown_check`）ときに、**フルログ復元トグルが OFF なら**次の後始末を行ってから終了する（ON のときは何もせず全て保持）。

| 💾終了時記憶 | 終了時の後始末 | 次回起動 |
|---|---|---|
| ON | 記憶スナップショットを保存 → フルログ（transcript＋session_id）だけ削除。記憶ノートは残す | 記憶ログの要約から再開 |
| OFF | 記憶ノートごと `/clear` 相当で全削除（削除前に `.todochat/trash/` へバックアップ） | 履歴なしで新規に起動時挨拶 |

- 終了時記憶を残したい場合は、ユーザー側で「終了時記憶 ON・フルログ復元 OFF」を設定する運用を想定しており、この処理側では自動で要約を取り直すことはしない。
- **異常終了**（強制終了・クラッシュ・電源断など、正常終了パスを通らない場合）ではこの後始末は実行されない。直前の会話状態（transcript・session）がそのまま残るため、次回起動時は復元＋resume で続きから再開できる（意図的な挙動）。
- リロードや PC⇔スマホの合流では `pagehide` で終了予約が入るが、ハートビート（`/api/alive`）が生きていれば予約はキャンセルされるため、この後始末は誤発火しない。

実装: `reset_conversation_on_shutdown()`（`app/server.py`）。呼び出し元は `_shutdown_check()` と `/api/quit` ハンドラで、いずれも `finalize_memory_if_enabled()`（終了時記憶の保存）の**直後**に呼ぶ（終了時記憶が生きた session を使って要約するため、先にセッションを破棄してはいけない）。
