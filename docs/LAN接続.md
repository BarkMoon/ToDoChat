# スマホ等からのLAN接続ガイド

同じネットワーク（自宅Wi-Fi など）にあるスマホや別PCのブラウザから ToDoChat に接続するための、**初回設定**と**解除方法**をまとめる。

> ⚠️ **セキュリティ注意**
> LAN経由（PC以外の端末）からの接続には**接続トークン認証**が必要（PC本体＝loopbackはトークン不要）。
> ただしHTTP平文のため、トークンはLAN内では素で流れる。**信頼できるネットワーク（自宅Wi-Fi / VPN）でのみ公開すること。** 公共Wi-Fiでは使わない。

---

## 仕組みの概要

- ToDoChat 本体（`app/server.py`）は PC 上で HTTP サーバーとして動く。
- 待受アドレスは**アプリ内の ⚙️設定ウィンドウ →「接続モード」**で切り替える。設定は `projects.json` に保存され、**次回起動時に反映**される。
  - **LANモード（既定・`0.0.0.0`）**… 全ネットワークインターフェースで待ち受け、同一ネットワークの端末から `http://<このPCのIP>:8765/` で接続できる。
  - **ローカル限定（`127.0.0.1`）**… そのPC自身からしか繋がらない。
- 設定ウィンドウには現在の待受状態と「変更は次回起動時に反映」される旨が表示される。

環境変数で個別に上書きも可能（設定より優先）：
- `TODOCHAT_HOST` … 待受アドレス（`0.0.0.0`=LAN公開 / `127.0.0.1`=ローカル限定）。設定すると**アプリ内の接続モード設定は無視される**。
- `TODOCHAT_PORT` … ポート番号（既定 `8765`）

---

## 初回設定手順

### ステップA：このPCのLAN IPアドレスを確認

コマンドプロンプトで `ipconfig` を実行し、`IPv4 アドレス` を確認する。
自宅ルーター配下なら通常 `192.168.x.x`（例：`192.168.1.25`）。

> 複数のIPv4が出る場合、`192.168.56.x`（VirtualBox）や `172.x.x.x`（WSL/Hyper-V）は仮想アダプタなので除外し、ルーターと同じ帯（例 `192.168.1.x`）のものを使う。
> `start.bat` で起動すると、起動ログに接続すべきURLが自動表示される。

### ステップB：ファイアウォールでポート8765の受信を許可（自動）

Windows ファイアウォールが外部からの接続をブロックするため、受信許可ルールが1つ必要になる。

**通常は手動操作は不要。** ⚙️設定ウィンドウで接続モードを「LANモード」に切り替えると、アプリが受信許可ルール（`profile=private`）を**自動で追加**する（追加時に一度だけ管理者確認＝UACが出る）。「ローカル限定」に戻すと、この受信許可ルールは**自動で削除**される。

- `profile=private` … 「プライベート」に分類されたネットワーク（自宅Wi-Fi等）でのみ許可する安全側の設定。
- ルールは一度追加すれば残る（PC再起動後も有効）。既に設定済みの場合、再度LANモードを選んでもUACは出ない。

> 自動設定がうまくいかない場合の手動コマンド（管理者権限のcmd）：
> ```
> netsh advfirewall firewall add rule name="ToDoChat" dir=in action=allow protocol=TCP localport=8765 profile=private
> ```

### ステップC：起動

- 接続モードが「LANモード」になっていることを ⚙️設定ウィンドウで確認する（既定でLANモード）。ローカル限定にしていた場合は切り替えてから再起動する。
- 既に起動中の ToDoChat があれば、**ウィンドウとサーバーのcmd窓を先にすべて閉じる**。
  （閉じないと新しい起動が「ポート8765は使用中」で弾かれ、古いサーバーが残ってしまう）
- **`start.bat` をダブルクリック**して起動。
- 起動ログに次のような行が出れば成功：
  ```
  LAN     : 同一ネットワークのスマホ等からは http://192.168.1.25:8765/ で接続できます
  ```

### ステップD：スマホから接続（初回はトークン認証）

- スマホを **PCと同じWi-Fi** に接続。
- **初回のみ：** PC本体の ⚙️設定ウィンドウ →「接続トークン」に表示される**スマホ用URL**（`http://<IP>:8765/?token=xxxx`）をスマホのブラウザで開く。サーバーがトークンを検証してCookieを発行し、トークンをURLから除いたトップ画面へ遷移する（＝ログイン完了）。
- **2回目以降：** 通常どおり `http://<IP>:8765/` を開くだけ（Cookieが残っている限りトークン入力は不要）。
- Cookieが切れた／別ブラウザの場合はログイン画面が出るので、設定ウィンドウのトークンを手入力するか、スマホ用URLを再度開く。
- トークンが漏れた恐れがあるときは、設定ウィンドウの **🔑再生成** で新しいトークンにでき、既存端末の認証はすべて無効になる。

## 解除方法（LAN公開をやめて元に戻す）

### 1. ローカル限定の起動に戻す

- ⚙️設定ウィンドウ →「接続モード」を **「ローカル限定（127.0.0.1）」** に切り替え、アプリを再起動する。
  （`127.0.0.1` で待ち受けるので、そのPC以外からは繋がらない）

### 2. ファイアウォールの受信許可ルールを削除

**通常は自動。** 上記1で接続モードを「ローカル限定」に切り替えた時点で、受信許可ルールは自動削除される（削除時に一度だけUACが出る）。

自分で確認・削除したい場合は、**管理者権限のcmd**で：

```
netsh advfirewall firewall delete rule name="ToDoChat"
```

削除できたか確認：

```
netsh advfirewall firewall show rule name="ToDoChat"
```
→「指定された条件に一致する規則はありません」と出れば削除完了。

## トラブルシューティング

**スマホから開けない場合、まず「サーバーがどのアドレスで待ち受けているか」を確認する：**

```
netstat -ano | findstr :8765
```

- `127.0.0.1:8765 ... LISTENING` … **ループバック限定**。接続モードが「ローカル限定」になっている（または古いサーバーが残っている）。設定を「LANモード」にして全ウィンドウを閉じ、`start.bat` で起動し直す。
- `0.0.0.0:8765 ... LISTENING` … **LAN公開OK**。繋がらないならファイアウォール（ステップB）かネットワーク側を疑う。

| 症状 | 確認ポイント |
|---|---|
| `netstat` が `127.0.0.1` のまま | 接続モードがローカル限定。「LANモード」に切り替えて再起動（古いサーバーが残っていれば全部閉じる） |
| `0.0.0.0` なのに繋がらない | ファイアウォールのルール（ステップB）を確認。`profile=private` かつ現在の接続が「プライベート ネットワーク」か |
| そもそもIPが違う | スマホとPCが**同じWi-Fi**か。ゲストWi-Fiやモバイル回線だと別ネットワークになる |
| ルーターの端末間通信が禁止 | 一部ルーターの「プライバシーセパレータ / AP隔離」機能をOFFにする |

## 外出先からも使いたい場合

このガイドは同一ネットワーク（自宅LAN）向け。外出先から使うには VPN（Tailscale 等）で PC とスマホを同一仮想ネットワークに入れる方式を予定（ロードマップのステップ4）。トークン認証は入ったが、ポート開放でのインターネット直接公開は経路が暗号化されず攻撃面も大きいため**行わないこと**（外出先はTailscale経由が本命）。
